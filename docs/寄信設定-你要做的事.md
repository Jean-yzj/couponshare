# 寄信設定：你要做的三件事

2026-09-06 建立。程式端已經全部寫好並上線，缺的只有「憑證」與「DNS」——這兩樣我沒有權限做。
做完之後：忘記密碼會自己運作，1,418 封通知信才有辦法寄。

**在你做完之前，網站上的「忘記密碼？」按鈕會誠實地告訴使用者「信件功能還在設定中，請來信客服」，
不會謊稱已經寄出。** 所以不急也不會出事，但 529 位密碼登入的使用者現在還是只能找你。

---

## 一、開 Resend 帳號並拿 API 金鑰（約 5 分鐘）

### 為什麼是 Resend

Zeabur 自家的 ZSend 我試過了，回 `user has not been granted Z-Send access`，你的帳號沒有權限。
Resend 的免費額度是**每月 3,000 封、每日 100 封**，對忘記密碼綽綽有餘。

那 1,418 封通知信要分 15 天寄完——這聽起來慢，但**它正好就是正確做法**：一個從沒寄過信的
網域一次發 1,400 封，幾乎保證進垃圾桶。分批寄本來就是新網域的暖機標準流程。急的話
月付 20 美金可以一次寄完，但我不建議。

### 步驟

1. 到 https://resend.com 註冊（帳號要你自己開，我不能代你註冊）
2. 左邊 **API Keys** → **Create API Key**
   - Name：`couponshare-production`
   - Permission：**Sending access**（不要給 Full access，這把金鑰只需要寄信）
   - Domain：先選 All domains，第二步做完再回來限縮
3. **金鑰只會顯示這一次**，複製起來

---

## 二、驗證寄件網域（約 10 分鐘 + 等 DNS 生效）

### 為什麼要用子網域，不要用 lazybearlife.com

`lazybearlife.com` 底下掛著你三十幾個專案。寄件網域的信譽是跟著網域走的——
如果 CouponShare 的信被大量標記為垃圾，受害的是整個根網域，包含你其他所有站的信。

**用 `mail.couponshare.lazybearlife.com` 隔離**，寄壞了也燒不到別人。

### 步驟

1. Resend → **Domains** → **Add Domain**
   - 填 `mail.couponshare.lazybearlife.com`
   - Region 選 **ap-northeast-1**（東京，離台灣使用者最近）
2. Resend 會給你三到四筆 DNS 記錄（MX、SPF 的 TXT、DKIM 的 TXT，可能還有 DMARC）
3. 到 **Cloudflare** → `lazybearlife.com` → **DNS** → 逐筆新增
   - **每一筆的 Proxy status 都要設成 `DNS only`（灰雲）**，不能是橘雲。
     橘雲會把記錄改寫成 Cloudflare 的 IP，郵件驗證就永遠不會過。
4. 回 Resend 按 **Verify**（DNS 生效通常幾分鐘，最久 24 小時）

---

## 三、把兩個值填進 Zeabur（約 2 分鐘）

Zeabur → couponshare 專案 → **app 服務**（不是 postgresql）→ **Variables**：

| 變數名 | 值 |
|---|---|
| `RESEND_API_KEY` | 第一步複製的金鑰 |
| `EMAIL_FROM` | `CouponShare <noreply@mail.couponshare.lazybearlife.com>` |

存檔後服務會自己重啟。

> **不要用終端機的 `zeabur variable list` 檢查**——那個指令不加 `--json` 會把所有變數的值
> 原樣印在畫面上，這個專案已經因此外洩過一次機密。用網頁後台。

## 做完跟我說，我會做這些驗證

1. 容器內確認兩個變數讀得到（只印有沒有，不印值）
2. 用一個**不存在**的信箱打 `/api/v1/auth/forgot-password`，確認回 200 且不洩漏帳號存在與否
3. 請你用自己的帳號實際跑一次忘記密碼，我從稽核日誌確認 `delivered: true`
4. 檢查信有沒有進垃圾桶（這一步只有你看得到，要麻煩你回報）

驗證通過後，才會進到 1,418 封通知信那件事——那件我會另外寫一份計畫給你過目，
包含文案、退訂機制、分批節奏，不會直接寄出去。
